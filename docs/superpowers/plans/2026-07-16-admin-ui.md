# Admin UI Implementation Plan (phased)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax. Execute **one phase at a time** with a review checkpoint between phases. Backend + testable FE logic (guard/store/services) follow TDD; `.vue` pages are not unit-testable in this repo (Vitest `environment: 'node'`, no `@vue/test-utils`) and end with a **manual verification** step instead.

**Goal:** A permission-gated `/admin` section in judge-portal (problems, judge servers, roles↔permissions, users↔roles), plus the backend write endpoints + permissions it needs.

**Architecture:** Nested `/admin` route with an `AdminLayout` sidebar; a `router.beforeEach` guard that awaits user load and checks `authStore.hasPermission`; new backend endpoints `PUT /roles/{id}/permissions`, `GET /users`, `PUT /users/{id}/roles`; three new permissions seeded via Flyway V5. Everything gated by permission on both router (redirect `/403`) and backend (403).

**Tech Stack:** Vue 3 + Pinia + vue-router 4 + Tailwind v4 + shadcn-vue + axios + Vitest (node env); Spring Boot 3.4 + Spring Security 6.4 + MapStruct + Flyway + JUnit/MockMvc/spring-security-test.

## Global Constraints

- Gate every admin capability by **permission** via `hasPermission(...)` / `@PreAuthorize("hasAuthority('...')")`, never by role. Backend enforces independently of the FE guard.
- FE services: singleton classes in `src/services/`; GET methods take `signal: AbortSignal` first; mutations take a body, no signal. All responses are `ApiResponse<T>`. Use `useFetch` for lists, `useToast().triggerToast(msg,type)` for feedback, shadcn `Dialog` for confirms.
- Assignment endpoints take **names** (`{ permissions: string[] }`, `{ roles: string[] }`) and **replace** the whole set; unknown name → 400 `AppException`.
- New permissions + UUIDs (Flyway **V5**, released migrations V1–V4 are immutable): `role:update`→`a1000000-0000-0000-0000-000000000007`, `user:read`→`…008`, `user:update`→`…009`. ADMIN role UUID `626c2558-a7d5-4fa4-9161-9bec2ae74076`.
- Backend tests: `cd judge-api && ./mvnw -q -Dspring.profiles.active=test -Dtest=ClassName test`. FE tests: `cd judge-portal && npx vitest run <file>`; type-check `npm run type-check`.
- Admin permission set (for the Header link + reused in the guard defaults): `problem:create`, `problem:update`, `problem:delete`, `judgeserver:read`, `role:read`, `user:read`.

- [ ] **Step 2: Run → fails.**

- [ ] **Step 3: Implement** — `adminGuard.ts`:

```ts
export interface AdminRouteMeta {
  permissions?: string[]
}

export interface AdminAccessContext {
  isAuthenticated: boolean
  hasPermission: (permission: string) => boolean
}

export type AdminAccess = 'allow' | 'login' | 'forbidden'

export function resolveAdminAccess(meta: AdminRouteMeta, ctx: AdminAccessContext): AdminAccess {
  const required = meta.permissions
  if (!required || required.length === 0) return 'allow'
  if (!ctx.isAuthenticated) return 'login'
  return required.some((p) => ctx.hasPermission(p)) ? 'allow' : 'forbidden'
}
```

router.beforeEach(async (to) => {
  const meta = (to.meta ?? {}) as { permissions?: string[] }
  if (!meta.permissions) return true
  const authStore = useAuthStore()

    hasPermission: authStore.hasPermission,

  if (access === 'login') return { path: ROUTE_PATH.PROBLEM }
  return { path: ROUTE_PATH.FORBIDDEN }
})

public RoleResponse updatePermissions(UUID id, Set<String> names) {

}
